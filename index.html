01 Why this role

I've been waiting for a brief like this one.

Most "AI engineer" roles today are prototyping dressed up as production. This one is the real thing — applied engineering, not research. Shipping a RAG pipeline over a real document corpus. Standing up a knowledge graph that becomes the system-of-record. Owning it on a ground-floor team.

That's the exact shape of work I've been doing for the last two years at Sprouts AI and Resilience Inc — and frankly, it's what I came to Chicago to build. RAG is where retrieval, structure, and language models finally stop being three separate conversations. Knowledge graphs are how you turn a pile of PDFs into something a company can actually reason over.

I don't want to write another paper. I want to ship the platform.

02 How I think about it

A RAG + knowledge graph system,
the way I've actually shipped it.

Below is the reference architecture I've deployed on Azure in production — every box corresponds to code I've written and owned, not a slide.

01
Hybrid retrieval
Vector + BM25 in Azure AI Search with a cross-encoder reranker. Evaluated offline with MRR, nDCG, and recall@k before shipping.
02
GraphRAG fusion
Neo4j 2-hop traversals expand retrieved chunks into evidence subgraphs — the graph isn't decoration, it's part of the answer.
03
.NET-native
ASP.NET Core Minimal APIs, MediatR pipelines, Polly resilience, EF Core over Cosmos, Neo4j .NET driver. No Python stubs glued together.
04
Eval in the loop
OpenTelemetry traces every retrieval and generation. Dashboards track hallucination rate and citation coverage, not just latency.
